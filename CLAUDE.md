# CLAUDE.md — working on Bun Voyage!

An Android burger arcade-idle game, written in Kotlin. Progress is continuous: 12 classic restaurants plus a 500-restaurant World Tour (512 in all), each built pad by pad; nothing you buy is ever taken away. A light story (Hazel's Voyage Book) frames the trip, and gold stars give finished restaurants a late game. Gameplay uses a custom GLES3 toon renderer; menus use Jetpack Compose. Every asset is generated by scripts in `tools/`.

## Commands
```bash
./gradlew assembleDebug                                   # build
./gradlew :app:testDebugUnitTest                          # JVM tests incl. the restaurant-flow validator (~20 s)
python3 -I tools/blender/inspect_bvm.py <model|--all>     # inspect .bvm models
```
- **Blender** lives at `~/Applications/Blender.app/Contents/MacOS/Blender` and runs headless with `-b --factory-startup --python <script> -- <args>`. Its bundled Python has numpy; the system `python3` does not.
- **Testing:** use the `BunVoyage_720p` emulator (`-gpu swiftshader_indirect -port 5580`, `ANDROID_SERIAL=emulator-5580`, `wm density 320`). Don't use the shared Realme phone unless the owner says it's free; when they do, keep it awake with a harmless key press every 15 min (it sleeps after ~20 min).

## Rules that are easy to break
1. **`game/` has no Android imports and is deterministic.** Use `Rng`, never `kotlin.random` or the time.
2. **If you change gameplay numbers or rules, re-run `RestaurantFlowTest`.** That covers `World`, `Bot`, `Restaurant` (plans, costs, pacing knobs), `Layouts`, `Types` prices/cook times and `Economy` stats. It must pass: every restaurant completable by the bot inside its pacing window, pads reachable and non-overlapping, saves restore exactly.
3. **New mechanics need `Bot.decide` support**, or the flow test fails as restaurants become uncompletable for the bot.
4. **Assets are referenced by string name.** A missing model isn't drawn and a missing UI image shows a vector fallback, both silently. Check the names.
5. **Character models:** keep the part order `body, head, eyes, armL, armR, legL, legR, tail` and the anchors `@hat @hand @bubble`. Rigid-part animation relies on them.
6. **Debug-only UI stays behind `BuildConfig.DEBUG_AD_UNLOCK` / `DEBUG_TOOLS`.** Release must have no mock ads or cheats. Only the first restaurant (Bun Wagon) starts open in every build.
7. **Onboarding has no skip button**, by product requirement.
8. **Play sounds through `App.sfx(name)`** (it applies volume trims) **and haptics through `App.haptic(kind)`**.
9. **Don't add `packageScope` to the release `optimization {}` block**: it crashed release on start.
10. **Originality:** never copy art, audio, names or text from other games or brands.
11. Keep allocations out of the per-frame paths: `World.update`, `WorldView.draw`, `Renderer`.
12. **Never reset what the player bought.** A restaurant's progress is `SaveData.restaurants[storeId]` (pad ids done + partial payments); `World` restores it. Pad ids are plan positions, so only append to a restaurant's plan, never reorder it, or saves will map to the wrong pads.
13. **Story beat ids and gold-star bits are saved** (`SaveData.story`, `SaveData.gold`). Never rename or remove a beat in `game/Story.kt`; add new ones. Keep lines ≤ 72 characters and two sentences, and keep `Story.cues()` read-only. `StoryTest` and `GoldStarsTest` must pass.
14. **The 12 classic restaurants never change.**
    - `ClassicGoldenTest` fingerprints their plans, costs, layouts 1–8, store data, stats and a short simulation. Keep it green.
    - Only re-record it for a change the owner approved.
15. **The World Tour is append-only.**
    - Region ids and restaurant ids (`<region>_<01..20>`, `game/TourRegions.kt`) are saved, so never reorder or rename them.
    - Add regions at the end.
    - Tour changes must pass `TourTest`. Run `FULL_TOUR=true` before a release.

## Where things live
| What | Where |
|---|---|
| Game rules / one shift | `game/World.kt` (update order is documented in ARCHITECTURE §3) |
| Restaurants, build plans, pad costs, pacing | `game/Restaurant.kt` (validated by `RestaurantFlowTest`; classic frozen by `ClassicGoldenTest`) |
| World Tour: 25 regions × 20 (data, generator, story, UI) | `game/TourRegions.kt`, `game/Tour.kt`, `game/TourStory.kt`, `ui/screens/WorldTourUi.kt` (validated by `TourTest`; design in `docs/WORLD_TOUR_DESIGN.md`) |
| Upgrades, stores, skins, pets, themes, player stats | `game/Economy.kt` |
| Drawing the world, characters, bubbles, pads, cash stacks | `render/WorldView.kt` |
| Story: cast, beats, triggers, Hazel's tutorial tips | `game/Story.kt` (script: `docs/STORY_SCRIPT.md`) |
| Gold stars (late game, 3 per finished restaurant) | `game/GoldStars.kt` |
| Speech cards, cut-scenes, Voyage Book | `ui/screens/StoryUi.kt`; the story director and HUD trackers are in `GameScreen.kt` |
| GL loop, lighting (toon: coloured shade, highlight shoulder), weather, event → FX | `render/GameRenderer.kt`, `engine/Shaders.kt` |
| Save (per-restaurant progress, one wallet), rewards, daily systems | `data/GameRepo.kt`, `data/Progress.kt` |
| Navigation | `ui/AppRoot.kt` |
| Screens | `ui/screens/` |
| Widgets and palette | `ui/kit/`, `ui/theme/Theme.kt` |

The Kotlin paths above are relative to `app/src/main/java/com/ngstudio/burgerready/`.
