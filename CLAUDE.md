# CLAUDE.md — working on Bun Voyage!

An Android burger arcade-idle game with 10,000 levels, written in Kotlin. Gameplay uses a custom GLES3 toon renderer; menus use Jetpack Compose. Every asset is generated by scripts in `tools/`.

## Start with these docs
- `README.md` — overview, build commands, repository map
- `docs/ARCHITECTURE.md` — threads, frame loop, simulation, rendering, save format, coordinates
- `docs/DEVELOPER_GUIDE.md` — recipes for adding content, tuning workflow, debug tools, release checklist, known issues
- `docs/ASSET_CONTRACT.md` — model names, parts, pivots and anchors the engine depends on

## Commands
```bash
./gradlew assembleDebug                                   # build
./gradlew :app:testDebugUnitTest                          # JVM tests incl. all-levels validator (~15 s)
TUNE=true ./gradlew :app:testDebugUnitTest --tests "*LevelTunerTest*"   # re-tune level targets (~30 s)
python3 -I tools/blender/inspect_bvm.py <model|--all>     # inspect .bvm models
```
- **Blender** lives at `~/Applications/Blender.app/Contents/MacOS/Blender` and runs headless with `-b --factory-startup --python <script> -- <args>`. Its bundled Python has numpy; the system `python3` does not.
- **Testing:** use the `BunVoyage_720p` emulator (`-gpu swiftshader_indirect -port 5580`, `ANDROID_SERIAL=emulator-5580`, `wm density 320`). Don't use the shared Realme phone unless the owner says it's free.

## Rules that are easy to break
1. **`game/` has no Android imports and is deterministic.** Use `Rng`, never `kotlin.random` or the time.
2. **If you change gameplay numbers or rules, re-run the tuner and then the validator.** That covers `World`, `Bot`, `LevelGen`, `Layouts`, `Types` prices/cook times and `Economy` stats. The validator must report 0 failures.
3. **New mechanics need `Bot.decide` support**, or the validator fails as levels become unwinnable for the bot.
4. **Assets are referenced by string name.** A missing model isn't drawn and a missing UI image shows a vector fallback, both silently. Check the names.
5. **Character models:** keep the part order `body, head, eyes, armL, armR, legL, legR, tail` and the anchors `@hat @hand @bubble`. Rigid-part animation relies on them.
6. **Debug-only UI stays behind `BuildConfig.DEBUG_AD_UNLOCK` / `DEBUG_TOOLS`.** Release must have no mock ads or cheats. Only level 1 starts unlocked in every build.
7. **Onboarding has no skip button**, by product requirement.
8. **Play sounds through `App.sfx(name)`** (it applies volume trims) **and haptics through `App.haptic(kind)`**.
9. **Don't add `packageScope` to the release `optimization {}` block**: it crashed release on start.
10. **Originality:** never copy art, audio, names or text from other games or brands.
11. Keep allocations out of the per-frame paths: `World.update`, `WorldView.draw`, `Renderer`.

## Where things live
| What | Where |
|---|---|
| Game rules / one shift | `game/World.kt` (update order is documented in ARCHITECTURE §3) |
| Levels, difficulty, tutorials | `game/LevelGen.kt`; tuned targets in `app/src/main/assets/levels/targets.bin` |
| Upgrades, stores, skins, pets, themes, player stats | `game/Economy.kt` |
| Drawing the world, characters, bubbles, pads | `render/WorldView.kt` |
| GL loop, lighting, weather, event → FX | `render/GameRenderer.kt` |
| Save, rewards, daily systems | `data/GameRepo.kt`, `data/Progress.kt` |
| Navigation | `ui/AppRoot.kt` |
| Screens | `ui/screens/` |
| Widgets and palette | `ui/kit/`, `ui/theme/Theme.kt` |

The Kotlin paths above are relative to `app/src/main/java/com/ngstudio/burgerready/`.
